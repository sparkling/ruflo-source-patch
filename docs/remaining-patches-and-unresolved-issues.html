cwd

data integrity
320/320Ruflo #2633 — durable state follows raw cwd

Anchors durable Ruflo state to the project root so agent cwd drift cannot silently reset learning, metrics, AgentDB, or memory.

GitHub: open. Installed code still resolves important stores from raw process cwd without this target.

Retirement proof

daemon

process isolation

Keys daemon identity and deduplication to the project root, preventing one daemon per subdirectory while keeping different projects isolated.

The narrower spawn-lock work from #2407/#2484 is present; root identity remains unresolved under #2633.

Retirement proof

Starts from several subdirectories must converge on one process and lock; starts from distinct project roots must remain independent.

memory

silent write loss
22/22Ruflo #2621 — daemon/MCP writer race

Adds the shared writer lock, WAL-coherent reads, torn-image integrity gate, and stale-writer restart boundary for memory.db.

GitHub: closed incomplete. Native <db>.lock protects purge only; ordinary writers still do not share it.

Retirement proof

Daemon, MCP, CLI writers, and purge must share one cross-process lock and survive real concurrent read-modify-write tests without acknowledged loss.

GitHub: open, partial. Atomic event claims reduce repeated effects, but init still emits duplicate host surfaces.

Retirement proof

Plugin-native init must omit the standalone bundle, duplicate lifecycle hooks, and duplicate MCP registration while preserving helpers and explicit non-plugin modes.

host parity
11/11Ruflo #2854 — dual-host marketplace installer

GitHub: open. Upstream has no native reconciliation command for the two independently stored registries.

Retirement proof

Native commands must preserve disabled state, unrelated plugins, exact marketplace identity, dry-run semantics, and loud partial failure across both hosts.

What happens next

The right action depends on whether the gap is upstream behavior, release delivery, or issue bookkeeping.

Keep patched and monitored

  • cwd, daemon, memory, init, and plugin-hosts.
  • adr-template and adr-index until a version-bumped active cache proves parity.
  • brain-codex-skills until native plugin-root discovery works.

Do not add a patch

  • Brain #64 must be fixed in the native updater; a downstream Spine override would violate Brain’s operating model.
  • Brain #41/#44 should converge through #48, not through a more elaborate Bash parser.
  • Brain #52 needs issue closure only.

Retire only on local proof

  • Execute the real replacement, not a version-marker grep.
  • Require active marketplace/cache delivery where plugins are versioned separately.
  • Unknown or partially rolled-out replacements bias toward keeping the patch.
