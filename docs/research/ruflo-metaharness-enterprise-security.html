Security controls, evidence and the boundary of the claim

A deep source audit of Ruflo, MetaHarness, AgenticOW, RVM and RuVector’s RVF format—plus the way Semantic Builder composes them. The report asks a stricter question than “does a feature exist?”: what is enforced, by whom, under which default, and what evidence would survive an adversarial review?

Executive verdict

Credible security building blocks. Not a turnkey enterprise security boundary.

Ruflo has strong reusable primitives for policy, path/command safety, encrypted stores, telemetry consent and release consistency. MetaHarness adds static assessment, evaluation, red-team workflows and evidence artifacts. AgenticOW limits experimental memory blast radius. RVF and RVM contain real hash-chain, signature, capability and witness primitives. The composition becomes defensible only when default-on external identity, OS isolation, key management, durable audit and fail-closed release gates surround it.

Safe claim

“The stack can support enterprise AI governance, control testing and provenance when deployed within a hardened enterprise control plane.”

Unsafe claim

“The stack is intrinsically enterprise-secure, provides complete encrypted provenance, or is ISO/SOC/NIST/SLSA compliant.”

How the claims were tested

The audit combined Brain-guided source discovery, pinned source inspection, published-package checks, executable tests, workflow inspection, a current Semantic Builder implementation review, and three independent adversarial workstreams. A green ADR, README, scorecard or generated manifest was treated as intent until code and an enforcement path supported it.

Reproducibility and evidence-scope notes
  • The Ruflo dependency observation came from a clean public-registry install of @claude-flow/cli@3.38.12 with optional dependencies, then npm audit --omit=dev using npm 9.6.6 on 19 Aug 2026. It reported 37 advisories (24 moderate, 12 high, one critical); the critical path was optional @xenova/transformers → onnxruntime-web → onnx-proto → protobufjs@6.11.6. Results are lockfile/toolchain/time-sensitive and do not prove reachability.
  • The MetaHarness provenance observation is narrower than “no provenance exists”: registry metadata responses inspected on 19 Aug for metaharness@0.4.7, @metaharness/kernel@0.1.3, @metaharness/darwin@0.9.2, @metaharness/redblue@0.1.6 and @metaharness/host-rvm@0.1.2 did not expose an attestation.
  • AgenticOW’s source and npm 0.2.4 bytes matched at the inspected commit; its package test suite ran 11/11. Exact counts are point-in-time implementation evidence, not enterprise control-effectiveness evidence.

Control evidence matrix

Filter by implementation maturity. “Delivered” means source and behavior were found; it does not mean enabled, complete, independently certified, or effective in your deployment.

Command and path safety

Delivered

Ruflo’s SafeExecutor uses literal argv, no shell, executable allowlists, timeouts and buffer limits; PathValidator resolves symlinks and boundary-safe prefixes.

Strong primitives, but only at call sites that use them. They are not an OS sandbox.

Agentic policy and approvals

Opt-in

The policy engine models rules, principals, roles, tenant fields, capability envelopes, approvals, budgets, HMAC evidence and chained receipts.

Runtime defaults to legacy allow; only explicit enforce mode blocks. Tenant fields do not establish tenant isolation, and tool classification remains heuristic.

Prompt and output defenses

Opt-in

AIDefence, ChannelGuard and ToolOutputGuardrail detect/redact/reject known patterns; the MCP client offers a central hook.

Strict guardrail is environment-gated, heuristics are bypassable, and missing security packages can fail open.

MCP network boundary

Partial

Stdio and loopback are the safest defaults; the remediated bridge requires a token for public binding and gates terminal execution.

Other HTTP paths still allow optional auth. Enterprise remote MCP needs TLS, scoped identity and a gateway.

Data at rest

Opt-in

Ruflo implements AES-256-GCM with random IVs and tamper rejection; secure file helpers use 0600/0700 and atomic writes.

Encryption is off by default, plaintext compatibility remains, and the only shipped key source is an environment variable—not KMS/HSM lifecycle.

Plugin trust

Gap

Ruflo validates package names and has an integrity-verifier class.

In the reviewed 3.38.12 CLI manager/loader path, install does not enforce signature, publisher or capability checks and npm plugin code initializes in-process. Treat that path as fully trusted code.

MetaHarness assessment

Partial

MCP scans, threat models, OIA manifests, security benches, red/blue orchestration and deterministic evaluation produce useful review evidence.

Coverage is static and host-incomplete; malformed or missing surfaces can be SKIP/WARN/exit 0, so “healthy” is not a security attestation.

Generated MCP runtime

Gap

The MetaHarness web generator emits policy, timeout, audit and bearer-auth modules.

Its server omits the dispatch loop, imports auth without calling it, and never enforces its call counter. The minimal CLI template registers an mcp start command that the generated CLI does not implement.

Darwin execution isolation

Gap

Normal mode avoids a shell, scrubs environment, bounds time/output and lexically inspects variants.

Execution retains the user’s OS authority. Tier-2 can import variant TypeScript without calling the advertised inspection gate.

AgenticOW branch isolation

Delivered

Copy-on-write branches, tombstones, diff, checkpoint, rollback and promote passed the published 11-test suite.

This contains candidate memory state only. Promotion has no built-in reviewer/signature; persistence is unsigned plaintext JSON.

RVF evidence format

Partial

SHAKE-256 witness chains, Ed25519 signing, lineage records and attestation-binding structures are implemented and tested.

Post-quantum signing is TODO. The ENCRYPTED flag does not currently encrypt payload bytes; a test round-trips plaintext under that flag.

RVM capability and witness libraries

Partial

Capability attenuation, rights, expiry/replay structures, gate decisions, hash chains and bounded witness logs are real libraries.

P2 checks a non-zero commitment, actor id is zero, signed P3 accepts all-zero signatures, and default witness keys/signatures are unsuitable for production assurance.

RVM runtime isolation

Proposed

The type model describes hosted, WASM and bare-metal enforcement mechanisms.

Hosted sandbox mechanisms are unimplemented booleans, bare-metal evidence is forgeable in-memory state, and the WASM path registers lifecycle without an interpreter.

Release and dependency assurance

Partial

Ruflo stages and smoke-tests exact archives. MetaHarness runs CodeQL/audits, creates SPDX-shaped SBOMs and invokes npm publication with provenance.

Witness isn’t a required release gate and some native build/audit paths are non-blocking. Inspected registry responses did not expose attestations. A reproducible optional-inclusive Ruflo consumer audit found a critical optional chain plus other advisories; see methodology.

Ruflo telemetry consent

Delivered

The Funnel requires current explicit consent, excludes raw prompts/commands/paths/repository names, bounds its local queue, rechecks consent before HTTPS transport and deletes queue/identity on opt-out.

A strong boundary for Ruflo’s own funnel telemetry; it does not govern third-party LLM, MCP or provider data flows.

Tenant isolation

Gap

Project roots, namespaces and selected path guards reduce accidental crossover.

No reviewed component proves hostile tenant separation, per-tenant principals/ACLs, storage authorization, isolated backups or per-tenant keys. Namespaces are not a security boundary.

Ruflo ↔ MetaHarness integration

Gap

Ruflo correctly presents itself as a wrapper around MetaHarness.

The plugin helper pins metaharness@~0.3.0 while current npm is 0.4.7; its drift check misses that constant. Missing integration returns success:true, degraded:true.

Semantic Builder: the strongest composition reviewed

Semantic Builder does not simply inherit upstream security claims. Its accepted ADRs deliberately subordinate Ruflo, MetaHarness and AgenticOW to repository-local authority rules. The hz checkout was inspected at committed HEAD f46d92a; modified helper files, untracked GitHub state and an untracked orchestrator test were excluded from stable claims.

Authority separation

Ruflo is replaceable orchestration substrate, not ontology truth. MetaHarness is offline evaluation, not production authority. RVM/RVFA remain deferred. A witness proves attribution, not promotion authority.

Bounded advisory memory

AgenticOW 0.2.4 is pinned behind frontier binding, branch/depth/count/capacity guards, strict roots, 0600 files and no authority method. Candidate memory can be rolled back without contaminating the base.

Evidence closure

Deterministic canonical-JSON/SHA-256 records bind exact Git HEAD/tree/ancestry, predecessor ADR bytes, command bytes, filesystem before/after state and effect counters. Selected pre-existing authorities verify Ed25519 signatures; explicit non-claims deny promotion, release, publication and production authority.

Fail-closed filesystem

Tests reject relative, symlinked, permissive, non-empty or substituted roots; atomic no-clobber authority transactions survive SIGKILL and use stable-epoch reads.

Protected promotion

Generation-zero policy requires external evidence and unresolved findings yield changes-required. The normal developer path is distinct from protected preflight and protected CI.

Residual reality

Accepted ADRs are design commitments, not production certification. No finalized V1–V2 run receipt was committed at this snapshot. Direct pushes, enterprise IAM/KMS/SIEM, deployment isolation and independent operating-effectiveness tests remain outside the repository.

Why this mattersSemantic Builder improves the stack by making authority local, explicit and narrower than capability. It uses upstream tools as advisory/evidence substrates and refuses to infer authorization from a signature, a score, a swarm result or an ADR.

Top blockers to an enterprise claim

1 · No universal mediation

Policy, identity, output scanning and witness calls are not guaranteed on every MCP/tool/agent mutation path.

2 · Defaults are developer-friendly

Legacy allow, optional auth, opt-in encryption/guardrails and degraded-success responses can make absent controls look healthy.

3 · “Sandbox” exceeds implementation

Darwin and current RVM paths do not provide a hardened OS/microVM boundary; same-UID code retains ambient authority.

4 · Audit is not yet enterprise-grade

Local JSONL/bounded logs, swallowed writes, incomplete identity and no central immutable retention prevent strong non-repudiation.

5 · Supply-chain gaps remain

Plugin execution is fully trusted, release witness gates are incomplete, pins drift, and consumer dependencies include serious optional advisories.

6 · Compliance is organizational

No software package supplies governance ownership, HR/physical controls, legal duties, incident response or independent audit opinion.

A defensible deployment blueprint

Use the stack as an instrumented agent platform inside a conventional enterprise control plane. Promotion should require evidence from every layer, with unknown or degraded states failing closed.

1 · Harden the boundary

Per-project/tenant non-root container or VM; read-only root; restricted mounts; seccomp/AppArmor/SELinux; default-deny egress; process/token quotas; stdio/loopback MCP; remote access only through OIDC/mTLS gateway.

2 · Make controls explicit

Ruflo policy enforce; strict output guardrail; reviewed/pinned plugins; KMS-backed per-project keys; scoped workload identity; two-person approvals for irreversible operations; fail on degraded.

3 · Prove operation

Actor-bound signed events to SIEM/WORM; trusted time and retention; signed/provenanced artifacts; protected tags; independent red-team and restore exercises; recurring access/vendor/model-risk review.
