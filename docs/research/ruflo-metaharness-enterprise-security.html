Sales & technical enablement

Ruflo enterprise security, explained

A source-backed guide to the security capabilities you can confidently sell: what Ruflo itself ships, which plugin or package owns each control, how to demonstrate it, and the precise boundary between a strong product claim and an overclaim.

The proposition

Defence in depth around agent execution.

Ruflo combines content screening, code and dependency triage, a central policy-and-receipt plane, protected state, signed evidence, runtime observability and optional assurance integrations. Its differentiator is composition: the same orchestration plane that coordinates agents can insert checks before content is stored, before actions execute, after tools return, and before a release or learned change is accepted.

30-second pitch: “Ruflo gives engineering teams an agent orchestration platform with security controls at the content, tool, memory and evidence boundaries. It can detect prompt injection and PII, scan code and dependencies, enforce action policies and budgets, protect durable state, and produce traceable evidence—while remaining extensible through MetaHarness, AgentDB, RuVector and federation integrations.”

Lead with

Composable controls, one orchestration plane, measurable receipts, and explicit deployment modes.

Do not lead with

Compliance, universal sandboxing, or “secure by default.” Enterprise posture requires deliberate enablement and external IAM, keys, isolation and retention.

Four security boundaries, one execution plane

This is the clearest architecture story for a buyer. Ruflo can place controls around four moments in an agent workflow; external enterprise infrastructure remains the hard perimeter.

1 · Content ingressAIDefence, PII gate, prompt-injection detection, browser/WASM ingestion scans, channel and plan scanning.
2 · Tool & action executionAgentic policy engine, approvals, budgets, MCP authorization option, safe executor, path/input validation.
3 · State & egress0600/0700 persistence, atomic writes, optional AES-GCM, AgentDB namespaces, output guardrail, federation transforms.
4 · Evidence & releaseDecision receipts, observability, witness manifests, temporal histories, RVF lineage and MetaHarness assurance.
Enterprise perimeter: SSO/workload identity, KMS/HSM, non-root container or VM, default-deny network, SIEM/WORM retention, protected release workflow and human approval for irreversible change.

Static security triage

Shipped · A−

Surface: ruflo-security-audit 0.2.1, /audit, security-scan and dependency-check.

Owner: Ruflo CLI security.ts; the plugin supplies the operator workflow.

Deep/standard/quick code + dependency triage, secrets, CVE inventory and threat discovery. High/critical scan findings can fail the command. Regex/bounded triage—not full SAST.

AIDefence safety plane

Opt-in · B+

Surface: ruflo-aidefence 0.2.1, six aidefence_* MCP tools, security defend.

Owner: optional @claude-flow/aidefence 3.0.3 plus deterministic CLI fallback.

Pattern-based injection, jailbreak and PII detection; real browser and WASM ingestion call sites. The canonical three-gate pattern is not universal default enforcement.

Channel, plan & MCP composition guards

Shipped · A−

Surface: security channel-scan, scan-plan, composition-scan.

Owner: Ruflo CLI ChannelGuard and MCP composition inspector.

Inter-agent messages and high-risk plan findings can gate with exit 2; composition findings are advisory. Heuristics, not proof of exploitability.

Policy, approval & budget plane

Opt-in · A/B

Surface: ruflo policy, policy_evaluate, policy_status.

Owner: @claude-flow/security policy engine + CLI policy runtime.

Every local Ruflo MCP handler reaches one policy chokepoint. Rules, expiring approvals, capability envelopes and atomic spend limits are real; default mode is legacy allow.

Central tool-output guardrail

Opt-in · B

Surface: CLAUDE_FLOW_STRICT_GUARDRAIL=true.

Owner: @claude-flow/security ToolOutputGuardrail, called from the local MCP client.

One switch can redact or reject suspicious string output across local Ruflo tools. Traversal is bounded/heuristic and a missing security package fails open.

Secure execution primitives

Shipped · A−

Surface: typed validators, SafeExecutor, PathValidator, loader-env denylist.

Owner: @claude-flow/security and Ruflo CLI boundary validators.

Literal argv, no shell, allowlists, symlink-aware containment, timeouts and runtime input validation reduce injection and traversal risk where adopted.

Protected durable state

Shipped + opt-in

Surface: restricted persistence and CLAUDE_FLOW_ENCRYPT_AT_REST=1.

Owner: CLI fs-secure and AES-256-GCM vault.

0600 files, 0700 directories and atomic writes are default primitives. Authenticated encryption is off by default and enterprise key custody/rotation remains external.

Witness & regression provenance

Opt-in · B+

Surface: ruflo-core 0.2.6 witness skill and scripts.

Owner: Ruflo core plugin; Ruflo’s release CI uses the verifier.

Signed fix-marker manifest, SHA-256 source binding and temporal JSONL history detect regressions. Reproducible signing is integrity, not enterprise identity.

Federated trust & budget breakers

Opt-in · B+

Surface: ruflo-federation 0.2.1 and @claude-flow/plugin-agent-federation.

Owner: Ruflo federation package.

Ed25519 envelopes, trust policy, PII transforms, hop/USD circuit breakers and audit events are implemented. Enterprise use needs strict auth/JCS, private binding and durable audit.

MetaHarness assurance plane

Integrated · B

Owner: MetaHarness 0.4.7, Darwin 0.9.2 and RedBlue engines—not Ruflo core.

Static MCP scan, threat model, OIA drift, security benchmark and controlled red/blue reports. Wrappers can return degraded success; callers must inspect state and alert flags.

AgentDB memory substrate

Owner: AgentDB / @claude-flow/memory.

Namespaced persistent memory, vector/hybrid retrieval and graph relations. Retrieval guard options exist; memory is not automatically an authority, encrypted vault or WORM log.

Owner: RuVector/RVF Rust crates.

AIDefence: the content-security story

AIDefence is the strongest live demo because the buyer can see benign content pass and injected or sensitive content get flagged. Explain the three layers of ownership before the feature.

ruflo-aidefence 0.2.1Command, safety-specialist agent, safety-scan and pii-detect skills.
+
@claude-flow/aidefence 3.0.3Detection service, threat-pattern store, similar-threat search and mitigation effectiveness.
+
Ruflo Core MCPSix callable aidefence_* tools and selected real ingestion gates.

The canonical three-gate pattern

1PII before persistence

Call aidefence_has_pii before AgentDB or memory storage. Redact or quarantine rather than persisting raw sensitive material.

2Sanitize secret-like content

Call aidefence_scan for tokens, cookies and high-entropy blobs. Replace raw material with an opaque vault handle.

3Injection before model re-entry

Call aidefence_is_safe before scraped, retrieved or federated text re-enters a prompt. Quarantine a flagged payload.

What it detects

Instruction override, role switching, jailbreak markers, system-prompt extraction, encoding attacks, hypothetical framing, developer modes, delimiter abuse and common PII/secret patterns.

Where it is live

Ruflo has real selective gates for browser-extracted output and WASM gallery imports. security defend also has a deterministic fallback if the optional package is missing.

Learning, precisely

It stores threat patterns and learns mitigation effectiveness. AgentDB can accelerate similar-pattern search. Current learned patterns do not rewrite or expand the fixed regex detector automatically.

Position it correctlySay “composable, pattern-based safety gates with learning-backed triage.” Do not say “every Ruflo path is protected,” “complete PII detection,” or “the detector autonomously trains itself.”

Policy, authorization, budgets and protected state

This is the feature that moves Ruflo from “a collection of scanners” to a governed execution plane. Local Ruflo MCP actions reach one policy runtime capable of rules, approvals, capability constraints, budgets and receipts.

Mode 1Legacy

Compatibility posture. No-match allows. Good for migration, not an enterprise enforcement claim.

Mode 2Observe

Computes and records the decision but permits the action. Use to tune rules and measure false positives.

Mode 3Enforce

Blocks denied actions and exceeded budgets. This is the posture required for the policy claim.

What the engine can express

Principals and roles; action/resource constraints; allow, deny and approval outcomes; expiring limited-use approvals; capability envelopes; token/cost ceilings; HMAC evidence; hash-chained decision receipts.

Where the line sits

It governs local Ruflo MCP handlers, not every external MCP, native host tool or operating-system action. Tool classification is partly name-heuristic, and production approval issuance needs an authenticated enterprise identity adapter.

npx ruflo@3.38.12 policy init --mode observe
npx ruflo@3.38.12 policy evaluate '{"identity":{"id":"agent-1","type":"agent"},"action":{"type":"deploy","environment":"production"}}'
npx ruflo@3.38.12 policy budget set '{"id":"daily-model","action":"model.call","maxCostUsd":10,"periodMs":86400000}'
# After validating rules and receipts:
npx ruflo@3.38.12 policy init --mode enforce
Golden-path enterprise posturePolicy in enforce; strict output guardrail enabled; encryption enabled with externally managed per-environment keys; AIDefence installed and verified; stdio/loopback MCP or authenticated TLS gateway; pinned/reviewed plugins; persistent external audit; OS sandbox for untrusted code.

Semantic Builder: what you can build with Ruflo

The current hz checkout at bfb7544 is the worked example. Its strongest lesson is architectural: Ruflo is the engineering-plane orchestration substrate, while product truth, promotion and external authority remain local. No committed product src/, config/ or tests/ path imports or dispatches Ruflo directly.

Expert agent systems

Use Ruflo swarms, typed specialist prompts, tasks and shared claims to coordinate reasoners and escalation councils. The Queen coordinates and synthesizes; it does not become truth or promotion authority.

Memory-backed learning loops

Combine ruflo-intelligence, AgentDB, RAG memory and RuVector for retrieve → judge → distil → consolidate loops, precedent recall and derived causal/pattern relations.

Lifecycle automation

Use hooks and workers to retrieve context, observe work, capture telemetry, consolidate allowed evidence and request a governed experiment—without silently activating a result.

Adversarial engineering

Use MetaHarness to freeze tasks, routes, evaluators and model identities; collect independent producer/challenger receipts; make unresolved findings changes-required.

Reversible candidate memory

Semantic Builder pins AgenticOW 0.2.4 behind local root, depth, capacity and substitution guards, then uses branches and rollback for advisory memory.

Evidence-bound promotion

Local contracts bind Git HEAD/tree/ancestry, command bytes, file-state deltas, content locks and external Ed25519 checks. A signed receipt is evidence; a separate authority decides promotion.

Security as a cross-cutting gate

Dependency/advisory snapshots, static policy checks, source integrity and protected-CI consistency are local gates. AIDefence is a candidate capability, but no fail-closed AIDefence product boundary is currently admitted.

Model/cost/quality orchestration

Ruflo exposes model routing, cost telemetry, workflows, observability and evaluation levers. The application must qualify actual providers, receipts and economics before relying on them.

A replaceable substrate

Production capability-admission records require exact component, revision, health, failure behavior, authority ceiling and expiry. Optional infrastructure cannot become invisible authority.

The buyer storySemantic Builder demonstrates that Ruflo can accelerate a sophisticated multi-agent engineering organisation while a domain application keeps truth and irreversible authority outside the agent platform. That separation is a security strength, not a limitation.

How to talk intelligently with a security buyer

Say this

  • “Ruflo provides layered controls around agent content, actions, state and evidence.”
  • “The policy engine can enforce local Ruflo MCP rules, approvals and budgets when configured in enforce mode.”
  • “AIDefence is a composable pattern-based safety plane with structured decisions and learning-backed triage.”
  • “MetaHarness is an optional assurance engine that Ruflo invokes; the results are evidence, not certification.”
  • “Witness and RVF provide integrity/lineage primitives; enterprise identity and retention are integrated externally.”
  • “Semantic Builder keeps product truth and promotion authority separate from orchestration.”

Avoid this

  • “Ruflo is secure/compliant by default.”
  • “AIDefence protects every input and detects all PII.”
  • “Security Scan is a complete SAST/DAST platform.”
  • “All plugins are signed, sandboxed and least-privileged.”
  • “The evidence chain proves every decision was captured and authorized.”
  • “RVM/SLIM currently give Ruflo hardware-isolated zero-trust execution.”

Discovery questions

Threat model

Which agents, tools, MCP servers, providers and data sources are trusted? What irreversible actions exist?

Identity & approval

Which IdP/workload identity signs actions? Who can approve production or sensitive-data access?

Data boundary

Which classifications may enter prompts, memory, traces, backups or federation? Where must residency apply?

Execution boundary

What filesystem, network, process and credential capabilities does each agent need? Which workloads need WASM/container/VM isolation?

Evidence & retention

Which events must reach SIEM/WORM, under what retention, clock, key and legal-hold policy?

Failure policy

Which optional/degraded control must block? What happens when AIDefence, MetaHarness, AgentDB or audit storage is unavailable?

Standards positioning

Ruflo can generate technical evidence relevant to NIST CSF/AI RMF, OWASP LLM and Agentic Top 10, NIST SSDF, ISO 27001/42001 and SOC 2 control discussions. It does not provide an ISMS/AIMS, legal classification, management ownership, operating-period audit sample, independent opinion or certification. Say “supports control implementation and evidence gathering,” never “is compliant.”

What still completes the enterprise story

These are not reasons to undersell Ruflo; they are the integration plan that turns strong product primitives into a defensible deployment.

Default-on enforcement

Move policy from legacy to enforce, enable strict output scanning and encryption, and make required optional engines fail closed.

Enterprise identity & keys

Bind principals and signatures to SSO/workload identity, KMS/HSM custody, rotation, revocation and two-person approval.

OS-level isolation

Use non-root containers/VMs, read-only mounts, seccomp/AppArmor/SELinux, default-deny egress and scoped credentials. Ordinary agent permission manifests are not syscall enforcement.

Plugin trust

Pin, review and admit plugins as trusted in-process code. Stable release validation is strong, but runtime plugin signature enforcement is not yet wired.

Durable audit

Export actor-bound events to SIEM/WORM; alert on write failure; prove coverage, trusted time, retention, restore and incident response.

Independent assurance

Run adversarial and recovery exercises against the deployed composition, not only package unit tests or a generated scorecard.

Primary evidence ledger

Pinned source is used where practical. Plugin smoke scripts prove packaging contracts; behavioral claims rely on implementation call sites and tests.
